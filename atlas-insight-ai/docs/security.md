# Security

## Tenant isolation

- Postgres RLS on every tenant table; policies generated by
  `app.apply_workspace_policies()` (select: org member; insert/update/
  delete: EDITOR+). Organization tables have bespoke policies.
- API routes must call `requireWorkspace(workspaceId, minRole)` — it
  authenticates the session, verifies membership and role, and returns an
  RLS-scoped client. Authorization is never frontend-only.
- Storage: bucket policies authorize by `<workspace_id>/` path prefix.
- File query engine: physical tables are named by unguessable UUIDs, run
  under a SELECT-only role, and AI queries are restricted to the workspace's
  semantic-model table allowlist.

## RBAC

`OWNER > ADMIN > EDITOR > VIEWER` at the organization level, enforced in
SQL (`app.has_org_role`) and in the API (`requireWorkspace`). Certification
and member management require ADMIN+; destructive org actions require OWNER.

## Credentials

- Zod-validated, split from non-secret config.
- AES-256-GCM at rest (`src/lib/crypto.ts`, key from `ENCRYPTION_KEY`),
  random IV per encryption, auth-tag verified on decrypt.
- Stored in a table with RLS enabled and **zero policies** → service-role
  only; decrypted only server-side at connection time. Never sent to the
  client, never placed in AI prompts. The module boundary is designed so a
  Secrets Manager can replace it without touching callers.

## Query safety

READ ONLY by default everywhere: AST-based SQL validation (single SELECT,
forbidden statements/functions blocked), table allowlist, statement
timeouts, row caps, read-only sessions (Postgres), byte-billing caps
(BigQuery), SELECT-only role (files). Blocked queries are recorded with
status `BLOCKED` for audit.

## Application

- Input validation with Zod on every API route; output validated specs.
- XSS: React escaping; no `dangerouslySetInnerHTML`.
- CSRF: Supabase auth cookies are `sameSite=lax`; state-changing routes
  require the authenticated session.
- Secure cookies (`httpOnly`, `secure` in production) for workspace
  selection; Supabase manages session cookies.
- Secrets only in environment variables; `.env.example` ships empty.
- Audit log (`audit_logs`) for create/delete/change/execute actions with
  user, org, workspace, resource, result and metadata.

## AI safety

- Prompts never contain credentials.
- The model can only produce validated artifacts (SQL passes the read-only
  validator; dashboards pass the spec schema).
- `ai_runs` stores a prompt hash, not the prompt, plus provider/model/token
  telemetry.
